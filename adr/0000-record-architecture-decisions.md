# ADR-0000: 설계 결정을 ADR로 기록

- 상태: 승인
- 날짜: 2026-11-19
- 관련: [#1](https://github.com/Phantom-s-Lab/Phantom-cloud/issues/1)

## 맥락
- 플랫폼 재구축 과정에서 여러 설계 결정이 생기지만, 코드와 설정 파일에는 "무엇을 했는지"만 남고 "왜 했는지"는 남지 않음

## 결정
- 주요 설계 결정은 [`template.md`](template.md) 형식의 ADR로 `adr/` 디렉터리에 기록
- 작성 기준과 상태 정의는 [`README.md`](README.md)를 따름

## 검토한 대안
- 블로그에만 기록: 과정과 배움 위주라 결정의 근거만 빠르게 찾아보기 어려움

## 결과
### 이점
- 설계 결정의 근거가 문서로 남아, 시간이 지나도 결정의 근거를 다시 추적할 수 있음
- 결정이 바뀌어도 기존 기록을 대체 표시로 남기므로, 설계 이력을 남길 수 있음

### 트레이드오프
- 결정할 때마다 문서 작성에 시간 소요
- 기록을 꾸준히 유지하지 않으면 실제 플랫폼 구성과 문서가 어긋날 수 있음
