## 상태
- **제안**: 결정을 기록했고 아직 구현·검증 전
- **승인**: 구현 후 검증까지 완료
- **거부**: 검증 결과 채택하지 않음 (기록은 삭제하지 않고 이유를 남김)
- **대체됨(ADR-00XX)**: 이후 다른 ADR로 결정이 바뀜

## 작성 기준
아래 중 **하나라도 해당하면** ADR을 작성합니다.

1. 대안이 2개 이상 있었고, 비교해서 하나를 골랐다
2. 되돌리려면 마이그레이션이 필요하다
3. 여러 레포나 이후 작업의 전제가 된다
4. 권한, 인증, 네트워크 경계 등 보안·격리에 관련된다
5. 나중에 "왜 이렇게 했지?"라는 질문이 나올 것 같다

다음은 ADR 없이 Issue와 PR 설명으로 충분합니다.
- 정해진 설계를 그대로 구현하는 작업
- 설정값 조정, 버전 업데이트, 버그 수정
- 문서·오타 수정

판단이 애매하면 "6개월 뒤에 PR만 보고 이유를 알 수 있을까?"를 기준으로 합니다.

## 작업 흐름
설계 → ADR 작성(제안) → Issue → 브랜치 작업 → PR(검증 결과 첨부) → Merge → ADR 승인 (검증 실패 시 거부/대체)

이미 실행·검증이 끝난 결정을 사후에 기록할 때는 바로 승인으로 작성한다.
